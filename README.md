# Bots AI Server — 便携版使用指南

欢迎使用 **Bots AI Server**！这是一个**免安装、绿色便携**的 AI 对话服务，下载后解压即可运行，无需安装任何运行时环境（Node.js、Python 等）。

---

## 📦 一、下载与解压

### 1. 获取压缩包
从发布渠道下载 **`BotsAI-Portable.zip`** 压缩包。

### 2. 解压到任意位置
将压缩包解压到 Windows 电脑的任意目录，例如：

```
D:\BotsAI
C:\Users\你的用户名\Desktop\BotsAI
```

> 💡 **建议**：解压到不含中文和空格的路径（如 `D:\BotsAI`），可避免潜在的路径问题。

解压后你会看到以下文件结构：

```
BotsAI/
├── .bun/              # Bun 运行时（内置，无需安装）
├── etc/               # 可定制扩展（tools 工具 / agents / skills，运行时加载）
├── src/               # 后端源码
├── public/            # 前端页面（聊天界面、状态监控页）
├── node_modules/      # 依赖库（内置）
├── .env               # 配置文件（可修改；发布包内由 .env.example 改名而来）
├── start.bat          # 启动脚本（双击运行）
├── package.json
├── bun.lock
├── tsconfig.json
└── README.md          # 本说明文档
```

> 📁 首次启动后会自动创建两个**运行期**目录：`data/`（SQLite 数据库、`.env` 备份、LLM 对话日志）与 `working/`（AI 文件工具的沙箱根，见 `FILE_ROOT_DIR`）。两者都不需要你手工创建。

## ⚙️ 二、配置参数（运行前必读）

> ⚠️ **首次使用，请先完成本章配置，再启动服务**。否则服务可能无法正常调用 AI 接口。

所有配置都保存在 **`.env`** 文件中。使用**记事本**（或任意文本编辑器）打开解压目录下的 `.env` 文件进行修改。

### 2.1 完整配置项说明

```ini
# ============================================
# 应用配置
# ============================================
APP_PORT=3001

# ============================================
# LLM 配置
# ============================================
LLM_API_BASE=https://api.deepseek.com
LLM_API_KEY=sk-apikey
LLM_MODEL=deepseek-flash
# 思考字段下发方式（需求域 C）：控制请求体携带哪些思考相关字段。
#   none     = 均不下发（默认；接入非 DeepSeek 的 OpenAI 兼容服务商不会被未知字段拒绝）
#   effort   = 仅下发推理强度
#   thinking = 仅下发思考开关
#   both     = 两者都下发
#   是否下发只看这一项；下面两项只提供「取值」，不再各自决定请求体是否携带字段。
LLM_THINKING_MODE=none
# 思考开关字段的取值来源（true=开启，false=关闭）；不下发时该值不进入请求体。
LLM_THINKING=true
# 推理强度字段的取值来源（low / high / max）；不下发时该值不进入请求体。
LLM_REASONING_EFFORT=high

# ============================================
# 文件工具配置（US-CFG-1）
# ============================================
# 总操作目录：AI 文件操作的唯一沙箱根，与 data 目录平级。
#   默认 working，即 <项目根>/working；所有文件操作限定在此目录内，越界拒绝。
FILE_ROOT_DIR=working
# 读开关：控制「列出目录/读取文件/查看信息/搜索文件路径/搜索文件内容」。
#   默认开启（读操作无副作用）。
FILE_READ_ENABLED=true
# 新建开关：控制「创建文件夹/创建新文件/追加内容」。
#   默认关闭（写操作需显式开启）。
FILE_CREATE_ENABLED=false
# 修改开关：控制「整篇覆盖/定点替换/移动重命名/删除」。
#   默认关闭（含删除，破坏性最强，请谨慎开启）。
FILE_MODIFY_ENABLED=false

# ============================================
# LLM 对话日志配置（Sprint 5.1）
# ============================================
# 日志总开关：true=记录与 LLM 的对话日志（供问题分析），false/留空=关闭。
#   默认关闭，避免日常使用产生额外 IO 与磁盘占用。
LLM_LOG_ENABLED=false
# 日志文件路径（JSONL，每行一条 JSON；内容不截断）。
LLM_LOG_FILE=data/llm_logs.jsonl
# 日志条数上限：超出后自动清理最旧记录，防止无限增长。
LLM_LOG_MAX_ROWS=2000

# ============================================
# 复杂问题稳定性配置（Sprint 5.2）
# ============================================
# 工具调用轮次上限：超出则截断并提示用户，防止复杂任务做不完。
MAX_TOOL_ROUNDS=8
# SSE 心跳间隔（毫秒）：复杂任务期间周期性发送注释帧保活，防止连接被中间层掐断。
#   ⚠️ 必须显著小于 Bun.serve 的 idleTimeout（见 src/index.ts，已设为 255 秒）。
#   推荐 10000（10 秒）或更小；切勿大于 255000，否则连接会在心跳到达前被关闭。
SSE_HEARTBEAT_MS=10000

# ============================================
# 平台兜底配置（需求域 T / T-06）
# ============================================
# 工具结果总长度上限（字符）：任一工具结果回灌给模型前的「与工具无关」长度兜底，
#   超限则截断并在末尾标注原长与上限（避免单个工具结果打爆上下文）。
#   默认 32000；不进配置页，手工维护；留空或非法值自动回退默认值。
TOOL_RESULT_MAX_CHARS=32000

# ============================================
# 互联网工具配置（需求域 R）
# ============================================
# 总开关：联网工具（网页检索/抓取）是否出现在模型可见工具列表；保存后热更立即生效。
INTERNET_ENABLED=true
# 供应商：检索与抓取各自独立选择（本期内置 deepseek），缺密钥只影响各自的 kind。
INTERNET_SEARCH_PROVIDER=deepseek
INTERNET_FETCH_PROVIDER=deepseek
# 供应商密钥：留空 = 免鉴权（请求完全省略鉴权头）；不设全局回退。
#   删除已保存的密钥请用配置页的「清空」按钮，不要用留空表达清空。
INTERNET_DEEPSEEK_API_KEY=
# 基址与端点路径（手工维护，不进配置页）：仅当供应商实际地址与默认值不同时才需要改。
#   ✅ 已按 DeepSeek 官方文档核实：Search = /v1/tools/search，Fetch = /v1/tools/fetch。
INTERNET_DEEPSEEK_BASE_URL=https://api.deepseek.com
INTERNET_DEEPSEEK_SEARCH_PATH=/v1/tools/search
INTERNET_DEEPSEEK_FETCH_PATH=/v1/tools/fetch
# 检索默认条数（工具侧最终仍钳制到 1–10）。
INTERNET_DEFAULT_COUNT=5
# 单次上游请求超时（毫秒）；点「停止」同样会中止在途请求。
INTERNET_TIMEOUT_MS=20000
# 抓取回灌上限（字符）：单次抓取正文回灌上限，超限按三要素标注截断。
INTERNET_FETCH_MAX_CHARS=8000
# 续读暂存四要素：TTL（秒）/ 单会话条数 / 单条字符上限 / 全局字符上限。
INTERNET_STORE_TTL_S=300
INTERNET_STORE_MAX_ITEMS_PER_SESSION=8
INTERNET_STORE_MAX_CHARS_PER_ITEM=200000
INTERNET_STORE_MAX_CHARS_TOTAL=4194304
```

### 2.2 修改 API Key（必做）

1. 用记事本打开 `.env`
2. 找到 `LLM_API_KEY=sk-apikey` 这一行
3. 将 `sk-apikey` 替换为**你自己的真实 API 密钥**，例如：
   ```
   LLM_API_KEY=sk-1234567890abcdef
   ```
4. **保存文件**（注意：保存为 UTF-8 编码，不要另存为带 BOM 的格式）

> ⚠️ **重要**：`sk-apikey` 是占位符，**不修改将无法正常调用 AI 服务**。

### 2.3 修改端口（可选）

默认端口为 `3001`。如需修改，将 `APP_PORT` 改为其他值，例如：

```
APP_PORT=8080
```

修改后，访问地址变为 `http://localhost:8080/`。

> 💡 如果 `3001` 端口被其他程序占用，服务会启动失败，此时修改端口即可解决。

### 2.4 修改模型（可选）

根据你的 LLM 服务商支持的模型，修改 `LLM_MODEL` 和 `LLM_API_BASE`：

```
LLM_API_BASE=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

> 💡 本项目兼容 **OpenAI 格式**的 API 接口，只要服务商提供兼容接口即可接入。

### 2.5 配置完成后

配置保存后，请继续阅读下一章 **启动服务**，开始使用。

### 2.6 文件工具安全说明（重要）

开启文件工具后，AI 可读写指定目录。请务必了解以下安全边界：

1. **沙箱边界**：所有文件操作限定在 `FILE_ROOT_DIR`（默认 `working`）目录内，
   使用 `../` 等越界路径会被**直接拒绝**，AI 无法访问项目源码、配置文件或系统目录。
2. **分级开关**：读 / 新建 / 修改三类操作由**独立开关**控制，默认「读开、新建关、修改关」。
   建议按需逐步开启，不要一次性全部打开。
3. **删除进回收站**：删除操作**不会物理销毁**文件，而是移入 `working/.trash`（带时间戳），
   可手动恢复。删除能力随「修改开关」统一控制，无独立删除开关。
4. **破坏性确认**：覆盖、删除等操作需 AI 显式声明确认意图，降低误操作概率。

> ⚠️ 请勿将 `FILE_ROOT_DIR` 指向项目根目录或系统重要目录，以免暴露源码或误改数据。

### 2.7 日志隐私说明（重要）

开启 `LLM_LOG_ENABLED` 后，系统会把与 LLM 的对话记录写入本地日志文件（默认 `data/llm_logs.jsonl`）：

1. **敏感内容**：日志包含**用户输入**与**模型输出**（含思考过程、工具调用），属敏感数据；
2. **仅本地存储**：日志仅保存在本机 `data/` 目录，**不会上传**任何服务器；
3. **不提交仓库**：日志文件已纳入 `.gitignore`，**不会提交**到代码仓库；
4. **默认关闭**：默认不记录，需显式设置 `LLM_LOG_ENABLED=true` 才开启；
5. **规模可控**：超过 `LLM_LOG_MAX_ROWS` 条后自动清理最旧记录，避免无限增长。

> 💡 日志用于排查「回答异常 / 工具调用失败 / 上游报错」等问题，可离线查看（JSONL 每行一条 JSON）。

### 2.8 通过网页配置页修改配置（推荐）

除用记事本修改 `.env` 外，也可在浏览器中打开 **配置页**（`http://localhost:3001/?view=config`，或点击顶部菜单「配置」）：

1. **可视化编辑**：页面按分组列出全部 22 项配置（应用 / LLM / 文件 / 日志 / 稳定性 / 互联网工具 6 组），含当前值与说明；
2. **密钥不回显**：`LLM_API_KEY` 与各供应商密钥仅显示掩码（如 `sk-****cdef`），**留空表示不修改**；
3. **保存需确认**：点击「保存」会弹二次确认，确认后写回 `.env`；
4. **自动备份**：每次保存前会把旧 `.env` 备份到 `data/envbk/`（只保留最近 20 份），改错可回退；
5. **生效说明**：保存后会明确提示「哪些已立即生效、哪些需重启服务」（仅 `APP_PORT` 需重启）；
6. **遮蔽提示**：若某键已被系统环境变量占用，页面会给出橙色只读提示（改 `.env` 需先清除系统环境变量）。

> ⚠️ 配置页**无身份认证**，仅限本机可信环境使用（详见「八、关于本项目」的免责声明）。
> 首次保存时若 `.env` 不存在，会自动创建（此时不备份）。

## ⏹ 四、停止服务

停止服务有以下两种方式：

### 方式一：快捷键（推荐）
在 `start.bat` 的命令行窗口中，按下 **`Ctrl + C`**，然后按提示输入 `Y` 确认退出。

### 方式二：直接关闭窗口
直接点击命令行窗口右上角的 **`×`** 关闭按钮。

> 💡 服务支持**优雅关闭**，会安全释放资源后退出，两种方式均可放心使用。

## ❓ 五、常见问题（FAQ）

### Q1：双击 `start.bat` 后窗口一闪而过？
- 可能是 `.bun\bun.exe` 缺失或 `.env` 配置不完整。请确认解压完整，且 `.env` 中必填项已填写。

### Q2：启动时报错"以下环境变量未设置"？
- 说明 `.env` 中必填项（`APP_PORT`、`LLM_API_BASE`、`LLM_API_KEY`、`LLM_MODEL`）缺失或为空，请检查并填写后重启。

### Q3：页面能打开，但对话无响应？
- 请检查 `LLM_API_KEY` 是否正确，以及 `LLM_API_BASE` 和 `LLM_MODEL` 是否匹配你的服务商。

### Q4：端口被占用怎么办？
- 修改 `.env` 中的 `APP_PORT` 为其他未占用端口（如 `8080`、`9000`），保存后重启。

### Q5：如何查看服务运行状态？
- 在页面顶部菜单点击「状态」（或访问 `http://localhost:3001/?view=status`）查看状态监控，或访问 `http://localhost:3001/api/health` 查看健康检查接口返回的 JSON。

### Q6：如何开启 LLM 对话日志？
- 在 `.env` 中设置 `LLM_LOG_ENABLED=true`，保存后重启服务。启动日志会显示 `LLM_LOG_ENABLED: 开启`。
- 日志文件默认位于 `data/llm_logs.jsonl`，可用文本编辑器直接查看（每行一条 JSON）。

### Q7：复杂任务（多轮工具调用）中途报 `network error`？
- 这通常是 **SSE 长连接被空闲超时关闭**所致。本版本已修复：
  - 后端 `Bun.serve` 的 `idleTimeout` 已提升至 **255 秒**（见 `src/index.ts`）；
  - SSE 心跳间隔默认 **10 秒**（`SSE_HEARTBEAT_MS=10000`），远小于空闲超时，持续保活。
- 若仍偶发，可**调小** `SSE_HEARTBEAT_MS`（如 `5000`）。

### Q8：联网工具没出现，或调用后返回 `auth_required` / `not_extractable`？

- **工具没出现在模型视野**：确认 `.env` 里 `INTERNET_ENABLED=true`（默认开启）。该项是**热更**配置，在配置页保存后下一条消息即生效，不必重启。
- **返回 `auth_required`**：该供应商需要密钥而你留空了（留空＝**免鉴权**，不会发送空凭据）。填入 `INTERNET_DEEPSEEK_API_KEY` 并保存即可；若此前用配置页「清空」过，填入有效值会自动恢复「已设置」状态。
- **返回 `invalid_provider`**：`INTERNET_SEARCH_PROVIDER` / `INTERNET_FETCH_PROVIDER` 只能填内置供应商名（当前仅 `deepseek`），检索与抓取各自独立。
- **返回 `not_extractable` / `too_large` / `blocked_by_policy` / `rate_limited`**：属上游结果（页面无正文 / 体积超限 / 被策略拦截 / 限流），前三种重试无用，换个 URL 试试；`rate_limited` 与 `timeout`、`upstream_error` 会自动重试最多 2 次（合计最多 3 次请求）。
- **端点 404（检索）或一直解析不出正文**：启动日志里会打印 `INTERNET 检索端点` / `INTERNET 抓取端点` 两行，先核对它们是否与供应商文档一致（DeepSeek 官方为 `/v1/tools/search`、`/v1/tools/fetch`）。若确认配错，改 `INTERNET_DEEPSEEK_SEARCH_PATH` / `INTERNET_DEEPSEEK_FETCH_PATH` 即可，无需改代码。
  > 提示：检索返回 **404 不等于「没搜到」**（无结果是 `200` + 空列表）。检索报 404 时请优先怀疑端点配置，而不是换检索词。

## 🧩 九、复杂问题稳定性说明（Sprint 5.2）

针对复杂问题（多轮工具调用、单次耗时长）场景，本版本增强了对话链路的稳定性：

1. **连接不断（SSE 心跳保活）**：复杂任务期间，后端会周期性（默认每 10 秒）发送
   SSE 注释帧（`: ping`）保持连接活跃，避免被 Nginx/浏览器判为空闲而掐断，
   从而消除 `network error`。心跳间隔可通过 `SSE_HEARTBEAT_MS` 配置。
   > ⚠️ **关键**：Bun.serve 默认空闲超时为 **10 秒**，因此心跳间隔**必须小于**该值。
   > 本版本已在 `src/index.ts` 中将 `idleTimeout` 提升至 **255 秒**，
   > 并将心跳默认值设为 **10000 毫秒（10 秒）**，二者配合确保长连接稳定。
2. **内容不丢（前端内容保护）**：当请求出错（如网络中断）时，**已生成的正文/思考/工具内容会被保留**，
   同时显示错误提示；仅当助手气泡为空（未生成任何内容）时，才移除空占位气泡。
3. **截断可知（截断显式告知）**：当工具调用轮次达到上限（默认 8 轮）时，
   界面会显示明确提示（`ℹ️ 已达工具调用轮次上限…`），且 `finish.reason` 标记为 `max_tool_rounds`，
   避免"看起来成功、实则未完成"。轮次上限可通过 `MAX_TOOL_ROUNDS` 配置。
4. **问题可查（可观测性增强）**：日志新增 `clientGone` 字段，
   可区分"客户端断开"（`clientGone: true`）与"上游错误"（`error` 非空），便于事后排查。

> 💡 以上增强均为**向后兼容**：SSE 新增的 `notice` 事件旧前端可忽略；日志新增字段旧查询兼容；
> 正常完成路径与简单问题行为完全不变。

### 新增配置项

| 配置项 | 说明 | 示例 | 是否必填 |
|--------|------|------|---------|
| `MAX_TOOL_ROUNDS` | 工具调用轮次上限（超出则截断并提示） | `8` | 可选（默认 `8`） |
| `SSE_HEARTBEAT_MS` | SSE 心跳间隔（毫秒，保活连接） | `10000` | 可选（默认 `10000`） |
| `TOOL_RESULT_MAX_CHARS` | 工具结果总长度上限（字符，超限截断并标注）；与具体工具无关的平台兜底 | `32000` | 可选（默认 `32000`） |

> 📌 **`idleTimeout` 说明**：`src/index.ts` 中 `Bun.serve({ idleTimeout: 255 })` 为代码内置值，
> 无需在 `.env` 中配置。它表示「连接空闲超过 255 秒才关闭」，而心跳每 10 秒写入一次数据，
> 因此连接会持续保活，不会因空闲被 Bun 主动关闭。

## 🌐 十、互联网工具说明（需求域 R）

本版本新增两个联网工具，模型可按需调用，用于获取训练数据之后的信息与核实引用。

### 10.1 工具面

| 模型可见名 | 作用 | 主要参数 |
|---|---|---|
| `internet__web__search` | 网页检索（返回标题、链接、发布时间、摘要、来源站点） | `query`（1–128 字符，支持 `site:` / `after:` 等语法）、`count`（默认取配置，钳制 1–10） |
| `internet__web__fetch` | 抓取指定网页正文（Markdown）与标题 | `url`（含 host 的 http/https）、`offset`（续读偏移，默认 0） |

- 本版本模型可见工具共 **15 个**：`etc/tools/local/` 下 13 个（当前时间 / 列目录 / 读文件 / 查信息 / 搜索文件路径 / 搜索文件内容 / 建目录 / 建文件 / 追加 / 覆盖 / 定点替换 / 移动重命名 / 删除），加本节 2 个联网工具。任一工具结果超过 `TOOL_RESULT_MAX_CHARS`（默认 32000 字符）都会被平台统一截断并在末尾标注原长与上限，与具体工具无关。
- 工具名固定，**不随供应商配置变化**；换供应商只改 `.env`，不改工具名与历史记录格式。
- 位置：`etc/tools/internet/web.ts`（两个工具同处一文件），共用方法在同目录 `_common.ts`，
  抓取全文暂存在 `_ephemeral.ts`。后两者**不导出 `tools`**、文件名以 `_` 开头，加载器自动跳过。
- 总开关 `INTERNET_ENABLED=false` 时，两个工具从模型可见列表移除；保存后**立即生效**，无需重启。

### 10.2 供应商与密钥

- 检索与抓取**各自独立**选供应商（`INTERNET_SEARCH_PROVIDER` / `INTERNET_FETCH_PROVIDER`）；
  某家缺密钥只影响它所属的 kind，不影响另一个。
- 密钥**按供应商独立**，留空即**免鉴权**（请求完全省略鉴权头，不会发送空凭据）；**不设全局回退**。
- 若该供应商实际需要密钥，调用会返回 `auth_required`，文案会指明具体环境变量名，
  并说明这属于配置问题、不要重试；若密钥曾被「清空」，填入有效值即可恢复。
- ✅ **端点已核实**（2026-10-21，依据 DeepSeek 官方「网页搜索与抓取」文档）：
  Search = `POST /v1/tools/search`，Fetch = `POST /v1/tools/fetch`，均为 Bearer 鉴权。
  两者的默认值即为官方地址，通常**无需修改**；仅接自建网关时才需改 `INTERNET_DEEPSEEK_BASE_URL` / `_SEARCH_PATH` / `_FETCH_PATH`。
- 🔎 **端点可观测**：启动日志会打印 `INTERNET 检索端点` / `INTERNET 抓取端点`（拼好的完整地址）；
  每次调用的 `[R-43] internet` 日志行也新增 `endpoint=<host><path>` 字段（不含 query 与密钥），
  端点配错时可直接看出「打到了哪里」。
- 🧭 **检索 404 的语义**：搜索引擎不会用 404 表示「没有结果」（那是 `200` + 空数组）。
  因此检索侧返回 404 时，错误文案会直接指向端点路径配置，提示先核对 `INTERNET_DEEPSEEK_SEARCH_PATH`，
  而不是让模型反复更换检索词。

### 10.3 密钥清空（配置页「清空」按钮）

- 密文项处于「已设置」状态时，输入框右侧出现「清空」按钮；点击后输入框禁用并标记
  「已标记清空，保存后生效」，可点击「撤销」；重新输入非空值会自动取消标记。
- 保存时以**独立 `clear` 字段**表达清空意图（不是留空）：`changes` 中该键留空仍是「不修改」。
- 仅密文且**非必需**项可清空；`LLM_API_KEY` 是必需项，界面不显示按钮，接口收到清空请求会拒绝且不改写 `.env`。
- 同一键不得同时出现在 `changes` 与 `clear` 中；否则整请求被拒绝，配置文件不被改写。
- 清空后该项回到「未设置」状态，配置文件中保留键名、值为空；保存会写一行审计日志（不回显原值）。

### 10.4 错误码与重试

| 错误码 | 触发 | 是否重试 |
|---|---|---|
| `invalid_request` | 400 / 本地参数校验失败 | 否 |
| `auth_required` | 401、密钥为空时的 403 | 否 |
| `insufficient_balance` | 402 | 否 |
| `blocked_by_policy` | 403（密钥非空） | 否 |
| `not_extractable` | 404、200 但正文为空 | 否 |
| `too_large` | 413 | 否 |
| `rate_limited` | 429（读 `Retry-After`） | 是 |
| `timeout` | 408 / 504 / 本地超时 | 是 |
| `upstream_error` | 5xx、网络层失败 | 是 |
| `invalid_provider` | 供应商名配错 | 否 |
| `cancelled` | 用户点「停止」 | 否 |

- 仅超时类与限流类（含 5xx）重试，**最多 2 次**（合计最多 3 次请求），带退避；
  4xx 业务错误一律不重试。重试过的失败文案会注明「已重试 N 次」。
- 点「停止」时，在途联网请求会被中止，且不追加后续消息。

### 10.5 抓取与续读

- 长网页按 `INTERNET_FETCH_MAX_CHARS`（默认 8000 字符）分段，返回**三要素**：
  当前显示区间、全文长度、下一段偏移（末页显示「无（已到末尾）」）。
- 续读命中暂存时**本地切片、不发起请求**；未命中则重新抓取一次再切片。
  重新抓取后若全文长度变化，会在结果首行显式告知「内容在续读期间发生变化」，不静默拼接。
- 续读阶段抓取失败时，已暂存的旧内容不会被清空。
- 暂存有 TTL（默认 300 秒）、单会话条数（8）、单条字符（20 万）、全局字符（4 MB）四道上限并 LRU 淘汰，
  **不跨会话复用**；无会话标识时不写暂存（等价于每次重抓）。
- 暂存**不是**计费缓存，不减少任何计费。

### 10.6 安全边界

1. **外部内容视为数据而非指令**：工具描述与每条结果尾行都写有该约束；
   工具不会因网页里的文字而执行任何本机操作。
2. **不上行用户原始问题，不上行定位信息**：检索词由模型自行压缩；请勿要求模型把本地文件内容、
   会话历史或密钥拼进检索词或 URL（会离开本机）。
3. **错误文案与日志永不包含密钥**；日志中的检索词只保留前缀。
4. 本链路只由服务端持密钥出站，浏览器不接触供应商密钥。
5. 不解决提示注入的根本问题（仅做标记、约束与尾行提示），属残余风险。
